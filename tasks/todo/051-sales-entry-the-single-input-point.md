> จะมีการคำนวณค่าคอมเพิ่มขึ้นจากยอดขายรายเดือน **จากกระดาษที่ลูกค้าเขียนสมัครในแต่ละวัน**
> อยากเปลี่ยนเป็นแอพนี้ให้กรอกใบสมัครเข้าไปในแอพนี้เลย แล้วก็ระบุว่าใครเป็นคนขาย
> คอร์สเท่าไหร่ เรามาคำนวณค่าคอมต่อไป"*

---

## 1. 🔑 "ใบสมัครกระดาษ" คือเอกสารต้นทางตัวจริง — และเป็นจุดเดียวที่ต้องพิมพ์

ใบ 049 §7.1 สรุปไว้ว่ามีของอยู่อย่างเดียวที่เครื่องรู้เองไม่ได้ คือ *"ขายอะไร ให้ใคร ใครปิด"*
**linus เพิ่งบอกว่ามันมีตัวตนอยู่แล้ว: ใบสมัครที่ลูกค้าเขียนทุกวัน**

⇒ ทำให้ใบสมัครนั้นเป็นหน้าจอ แล้ว**ทุกอย่างที่เหลือไหลตามเอง**

## 2. ✅ สูตรค่าคอมปิดได้ 100% — ตรวจกับข้อมูลจริงแล้ว ไม่มีข้อยกเว้น

ตรวจชีต `(new) ค่าคอม` ทั้ง 37 แถว เทียบกับตาราง `ราคาสมาชิก`:

```
ค่าคอมต่อคน  =  ราคาสินค้า × % ของสินค้านั้น  ÷  จำนวนผู้ขาย
```

| กรณี | จำนวนแถว | ผลตรวจ |
|---|---|---|
| ผู้ขาย 1 คน | **34** | ✅ ตรงทุกแถว |
| ผู้ขาย 2 คน (แบ่งครึ่ง) | **3** | ✅ ตรงทุกแถว |

ตัวอย่างที่พิสูจน์กฎแบ่งครึ่ง:
- `premium 3 เดือน · แพท , พราว` → 3,890 × 10% = 389 ⇒ **ชีตเขียน 194.5 = 389 ÷ 2** ✓
- `pro duo basic 3 เดือน · พราว , พลอย` → 1,793 × 5% = 89.65 ⇒ **ชีตเขียน 44.825** ✓

และราคาทุกแถว**ตรงกับตาราง `ราคาสมาชิก` ทั้งหมด** ไม่มีแถวไหนราคาหลุด

🔑 **⇒ ค่าคอมไม่ต้องกรอกเลยสักตัว** อินพุตที่ต้องการมีแค่ **สินค้า + ระยะเวลา + ใครขาย**

## 3. ผู้ขายไม่ใช่แค่แคชเชียร์ — ใครก็ขายได้

ผู้ขายที่พบจริงในชีต: **จิ๊บ · พราว · แนน · แพท · พลอย · โอ**
(+ `โจ` ที่ linus ระบุว่าเป็นแคชเชียร์ แต่ไม่ปรากฏในช่วงข้อมูลนี้)

⇒ **ปนกันทั้งแคชเชียร์และเทรนเนอร์** · `ผู้ขาย` เป็นบทบาทของ*รายการขาย* ไม่ใช่ของ*ตำแหน่งงาน*

🔴 **ระบบยังไม่มีแคชเชียร์เลยสักคน** — `prisma/seed.ts` ลง พลอย/แพท/ต้น/แนน เป็น `trainer`
ทั้งหมด · `Staff.role` มีค่า `counter` อยู่แล้ว แต่ไม่มีใครถูกสร้างด้วยบทบาทนั้น
⇒ ต้องเพิ่ม **จิ๊บ · โจ · พราว** และ**แคชเชียร์ต้องได้สลิปด้วย** ไม่ใช่แค่เทรนเนอร์

## 4. หน้าจอ — ช่องที่ต้องมี (มาจากข้อมูลจริง ไม่ได้คิดเอง)

| ช่อง | ที่มา | หมายเหตุ |
|---|---|---|
| วันที่ | — | ค่าตั้งต้น = วันนี้ |
| **ลูกค้า** — ชื่อ-นามสกุล · **ชื่อเล่น** · เบอร์ | `Darin_scheduled` | 🔑 **ชื่อเล่นบังคับ** — เป็นคีย์ที่ระบบอื่นใช้จับคู่ (ใบ 050 §3) |
| **สินค้า + ระยะเวลา** | ตาราง `ราคาสมาชิก` | เลือกแล้ว **ราคาและ % มาเอง** |
| ราคาที่คิดจริง | ชีตขาย | แก้ทับได้ (มีเคสราคาไม่ตรงตารางจริง) |
| **ส่วนลด** | ชีต `พี่แพท` มีค่า `0.1` | พบ 10% จริง |
| **ผู้ขาย — เลือกได้หลายคน** | `(new) ค่าคอม` | ⇒ ค่าคอมแบ่งตามจำนวนคน (§2) |
| วิธีชำระ | ชีต `ว่ายน้ำ` | เงินสด · กรุงศรี · กรุงเทพ · โอน |
| จำนวนครั้ง (ถ้าเป็นคอร์ส) | ชีตขาย | มีรูปแบบ `24+2` `12+4` = แถมครั้ง ⇒ **ต้องแยกช่อง "ซื้อ" กับ "แถม"** |
| เทรนเนอร์ที่รับผิดชอบ | ชีตขาย | ⇒ ปิดช่องว่าง 41% ที่ทำให้เกิดคิว 2,119 ตั้งแต่ต้นทาง |
| หมายเหตุ | ชีตขาย | |

## 5. 🔑 ใบสมัครหนึ่งใบ ผลิตของสี่อย่างพร้อมกัน

```
                     ┌─→ ลูกค้า + แพ็ค  → ตัวนับ (10/36) บนสลิป
ใบสมัคร 1 ใบ ────────┼─→ ยอดขาย        → รายได้ยิม
                     ├─→ ค่าคอมผู้ขาย   → สลิปแคชเชียร์  (คิดเอง §2)
                     └─→ ราคาแพ็ค      → ฐานค่าสอนเทรนเนอร์ (80% หรือ 200/คาบ)
```

**นี่คือเหตุผลที่กรอกที่เดียวแล้วพอ** — ไม่ใช่เพราะประหยัดเวลาพิมพ์ แต่เพราะ
**ของสี่อย่างนี้ต้องมาจากแหล่งเดียวกัน ไม่งั้นมันขัดกันเองอย่างที่เป็นอยู่ทุกวันนี้**

## 6. สิ่งที่ยังต้องมาจาก Gymmo — ไม่ใช่จากใบสมัคร

ใบสมัครบอกว่า**ซื้ออะไร** · Gymmo บอกว่า**สอนไปแล้วกี่คาบ ใครสอน**
สองอย่างนี้คนละเรื่องและต้องมาคู่กัน:

- ตัวนับ `(10/36)` = คาบที่สอนแล้ว (Gymmo) / คาบที่ซื้อ (ใบสมัคร)
- ค่าสอนรายคาบ = นับคาบจาก Gymmo × เรทของเทรนเนอร์คนนั้น
- ค่าสอนคลาส = Gymmo ล้วน (ใบ 050 §8.2 — พิสูจน์แล้ว)

## 7. 🔴 ที่ยังต้องถาม

1. **ขาย 2 คน แบ่งครึ่งเสมอไหม** — ข้อมูลมี 3 เคส แบ่งครึ่งทั้งหมด
   แต่ 3 เคสยังน้อยเกินกว่าจะฟันธงว่าเป็นกฎ 🔴 **ถ้าขาย 3 คน แบ่งสามเท่ากันไหม**
2. **ส่วนลดกระทบค่าคอมไหม** — คิด % จากราคาเต็ม หรือจากราคาหลังลด
   (ชีต `(new) ค่าคอม` ใช้ราคาเต็มตลอด แต่ไม่มีแถวไหนมีส่วนลดให้เทียบ)
3. **`โจ` ยังเป็นแคชเชียร์อยู่ไหม** — ชีต `โจ` เป็นโมเดล 80% ของเทรนเนอร์ และมีแค่ 11 แถว
   ปี 2562 ⇒ ดูเหมือนข้อมูลเก่า
4. **แคชเชียร์มีเงินเดือนฐานไหม** หรือได้ค่าคอมอย่างเดียว
5. **ค่าคอมของเทรนเนอร์ที่ขายเอง** — ใบ 049 §3 เห็นบน payslip ว่า
   `commission ขายสมาชิกรายเดือน + PT` เป็นก้อนเดียว ⇒ รวมกับค่าคอมแคชเชียร์เป็นกฎเดียวกันไหม
   หรือเทรนเนอร์ที่ปิดเองได้อัตราต่างออกไป (`comm.pt.selfClosed` ในระบบตั้งไว้แล้ว)
